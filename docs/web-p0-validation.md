# Web P0 实现与验证记录

验证日期：2026-10-21。实现提交：`3d56da2d47d106580a1bb438c013434053cf80fe`。

本版打通浏览器、FastAPI 网关和真实 Core 的聊天、工具、人工审批及报告链路，并交付三栏工作台、浏览器刷新恢复、源代码和演示素材。运行组合限定为 **Loop + Local**。

## 已实现的主流程

- 本机一次性启动口令、HttpOnly Cookie、同源 HTTP/WebSocket、Host/Origin/CSRF 校验。
- 每个 Web Session 持有独立 Core TCP，后台执行长 RPC；页面断开不终止任务。
- 会话创建与请求查询、同请求去重、并发准入、消息流、工具详情和失败尝试。
- 允许/拒绝一次、真实主/子任务来源、过期处理、重复决定防护；HTTP 取消不取消已受理决定。
- 子任务输出单独展示，不拼接进主回答；Skill 使用记录来自真实事件。
- 原子快照与增量、订阅代次、会话摘要版本保护、慢订阅隔离和有界投影。
- `core.describe` 与 owner-only `run.get_result`；报告关联 Core 的本轮提交结果，避免失败轮次引用上一轮答案。
- 报告来源、截断说明与 Markdown 下载；同步任务共享，关闭/切换状态不会被旧结果覆盖。
- 无 Key 的脚本化 Provider 演示，实际文件、Shell、权限和 Core 调用都保持真实。

另外验证了 1,000 次工具事件的投影上限、过长审批参数不能批准、子 run 序号与输出隔离、容量异常不残留报告、同步等待者取消和关闭期间的旧结果处理。它们是状态和集成测试，不应称为完整浏览器压力基准。

## 浏览器测量

环境：Windows 10 build 19045，AMD Ryzen 5 9600X，12 逻辑处理器，31.1 GiB 可见内存；Ubuntu-20.04 WSL2；Python 3.12.13；Windows Node 22.19.0；Chromium 156.0.8078.4。使用生产构建、已启动服务、离线 Provider。

| 指标 | 样本数 | 实测 |
| --- | --- | --- |
| 刷新至原 run 快照可操作 | 30 | p95 **121.9 ms** |
| 浏览器收到事件至 React 提交后下一绘制时机 | 45 | p95 **33.6 ms** |
| 新浏览器上下文打开至会话可操作 | 10 | 最大 **221.9 ms** |

p95 使用 nearest-rank。刷新数值由浏览器导航起点到页面断言完成时测量，包含断言开销；事件展示测量使用同一浏览器时钟和 requestAnimationFrame，不代表物理屏幕扫描完成时间。冷页面使用新浏览器上下文和已有认证 Cookie，不包括安装、服务启动或首次身份绑定。模型网络延迟与端到端用户任务耗时没有计入。

原始样本、环境和素材 SHA-256 见 [web-validation-metrics.json](assets/web-validation-metrics.json)。这组数据描述本机固定配置，不能写成生产规模、真实模型响应速度或优化提升比例。
